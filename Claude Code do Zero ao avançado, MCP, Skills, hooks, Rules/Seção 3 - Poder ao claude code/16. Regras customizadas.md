# Regras customizadas

## Regras (rules)

- Regras sempre são injetadas no prompt.

Arquivos de instruções modulares em .claude/rules/ que carregam junto com CLAUDE.md.

Uma rule pode ter escopo de caminho com frontmatter YAML paths: para que carregue apenas quando Claude lê um arquivo correspondente, mantendo o contexto enxuto até que seja relevante.

*Para instruções específicas de tarefas que não precisam estar em contexto o tempo todo, use skills em vez disso, que carregam apenas quando você as invoca ou quando Claude determina que são relevantes para seu prompt*

## Estrutura

seu-projeto/
├── .claude/
│   ├── CLAUDE.md           # Instruções principais do projeto
│   └── rules/
│       ├── code-style.md   # Diretrizes de estilo de código
│       ├── testing.md      # Convenções de teste
│       └── security.md     # Requisitos de segurança

Coloque arquivos markdown no diretório .claude/rules/ do seu projeto. Cada arquivo deve cobrir um tópico, com um nome de arquivo descritivo.

Todos os arquivos .md são descobertos recursivamente, portanto você pode organizar regras em subdiretórios como frontend/ ou backend/

Regras sem frontmatter paths são carregadas na inicialização com a mesma prioridade que .claude/CLAUDE.md.

## Regras com escopo de caminho

```txt
---
paths:
  - "src/api/**/*.ts"
---

# Regras de Desenvolvimento de API

- Todos os endpoints de API devem incluir validação de entrada
- Use o formato de resposta de erro padrão
- Inclua comentários de documentação OpenAPI
```

As regras com escopo de caminho são acionadas quando Claude lê arquivos que
correspondem ao padrão, não em cada uso de ferramenta.
