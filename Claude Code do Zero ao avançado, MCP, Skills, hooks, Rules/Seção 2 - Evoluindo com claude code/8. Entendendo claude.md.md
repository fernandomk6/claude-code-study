### O claude.md é carregado a cada sessão, portanto, inclua apenas itens de ampla aplicação.

Base de conteúdo do claude.md.

| Incluir | Excluir |
| --- | --- |
| O que o Claude não consegue adivinhar | Coisas que o Claude consegue descobrir lendo o código |
| Regras de estilo que diferem do padrão | Convenções que o claude já conhece |
| Nomeclatura de branchs, convenções, coisas que não mudam | Informações que mudam com frequência |
| Decisões especificas para o projeto | Explicações longas ou tutoriais |
| Particularidades do ambiente, variáveis de ambiente | Descrições de arquivo |

### Como estruturar o claude.md?

- Use arquivos CLAUDE.md quando quiser guiar o comportamento de Claude.
- Claude os lê no início de cada sessão.
- Trate CLAUDE.md como o lugar onde você escreve o que de outra forma teria que re-explicar.

*Se uma entrada é um procedimento de várias etapas ou importa apenas para uma parte do codebase, mova-a para uma skill*

- Instruções específicas, concisas e bem estruturadas funcionam melhor.
- Alvo de menos de 200 linhas por arquivo CLAUDE.md

---
### Estrutura
Use cabeçalhos markdown e bullets para agrupar instruções relacionadas.

### Especificidade:
Escreva instruções que sejam concretas o suficiente para verificar. Por exemplo:
- “Use indentação de 2 espaços” em vez de “Formate o código adequadamente”
- “Execute npm test antes de fazer commit” em vez de “Teste suas alterações”
- “Os manipuladores de API vivem em src/api/handlers/” em vez de “Mantenha os arquivos organizados”

### Consistência
Se duas regras se contradizem, Claude pode escolher uma arbitrariamente.
Revise seus arquivos CLAUDE.md, arquivos CLAUDE.md aninhados em
subdiretórios e .claude/rules/ periodicamente para remover instruções
desatualizadas ou conflitantes.

---

### Importe arquivos adicionais
Os arquivos CLAUDE.md podem importar arquivos adicionais usando a sintaxe 
`@path/to/import.`
Caminhos relativos e absolutos são permitidos. 

*Para mencionar um caminho em seu CLAUDE.md sem importá-lo, envolva-o em backticks: escrever `@README` mantém o texto literal, enquanto @README fora de backticks importa o arquivo.*

### CLAUDE.local.md
- Para preferências pessoais por projeto que não devem ser verificadas no controle de versão, crie um CLAUDE.local.md na raiz do projeto.
- Ele carrega junto com CLAUDE.md e é tratado da mesma forma.
- Adicione CLAUDE.local.md ao seu .gitignore para que não seja confirmado.

### CLAUDE.md aninhados

- Claude Code carrega CLAUDE.md e CLAUDE.local.md do seu diretório de trabalho atual e de cada diretório acima dele. Execute Claude Code em foo/bar/ e ele carrega instruções de foo/bar/CLAUDE.md, foo/CLAUDE.md e qualquer arquivo CLAUDE.local.md ao lado deles.
- Todos os arquivos descobertos são concatenados em contexto em vez de se sobreporem.
- As instruções mais próximas de onde você iniciou Claude são lidas por último.

### .claude/rules/

Coloque arquivos markdown no diretório .claude/rules/ do seu projeto.
Cada arquivo deve cobrir um tópico, com um nome de arquivo descritivo como testing.md ou api-design.md.
Todos os arquivos .md são descobertos recursivamente, portanto você pode organizar regras em subdiretórios como frontend/ ou backend/

seu-projeto/
├── .claude/
│   ├── CLAUDE.md           # Instruções principais do projeto
│   └── rules/
│       ├── code-style.md   # Diretrizes de estilo de código
│       ├── testing.md      # Convenções de teste
│       └── security.md     # Requisitos de segurança

Regras sem frontmatter paths são carregadas na inicialização com a mesma prioridade que .claude/CLAUDE.md

#### Regras com escopo de caminho
As regras podem ser escopo para arquivos específicos usando frontmatter YAML
com o campo paths.
Essas regras condicionais se aplicam apenas quando Claude está
trabalhando com arquivos que correspondem aos padrões especificados.

```markdown
---
paths:
  - src/api/**/*.ts

---

# Regras de Desenvolvimento de API

- Todos os endpoints de API devem incluir validação de entrada
- Use o formato de resposta de erro padrão
- Inclua comentários de documentação OpenAPI
```

Regras sem um campo paths são carregadas incondicionalmente e se aplicam a todos os arquivos.

Você pode especificar vários padrões e usar expansão de chaves para corresponder várias extensões em um padrão:

```txt
---
paths:
  - "src/**/*.{ts,tsx}"
  - "lib/**/*.ts"
  - "tests/**/*.test.ts"

---
```
